# Navigator layer rules

## What `build-layer` produces

- One layer per ATT&CK domain: `domain` is "enterprise-attack",
  "ics-attack" or "mobile-attack". A Navigator layer holds one domain, so a
  report mapped to Enterprise and ICS gives two layers. Their names end in
  "(Enterprise ATT&CK)" and "(ICS ATT&CK)".
- `versions`: `attack` is the verified major version as a string (for
  example "19" for 19.2), `navigator` is the current Navigator release,
  `layer` is "4.5".
- One entry per technique and tactic, with the `tactic` shortname set so
  the highlight appears only under the tactic the source supports.
- Colour by confidence: High `#8ec843` (score 100), Moderate `#ffe766` (66),
  Low `#ff6666` (33), with a matching legend.
- Each mapped sub-technique as its own entry. Its parent is present as a
  **parent display entry**: `showSubtechniques: true`, no score, empty
  colour, and metadata `mapping: parent display entry (not a mapped
  procedure)`. Parent display entries make the Navigator expand the parent
  to show the sub-technique. They are never counted as mappings. The script
  prints direct mappings and parent display entries as separate counts.
- `layout.expandedSubtechniques: "annotated"` so mapped sub-techniques
  show on import.
- The cell comment holds the confidence and, for each mapping in the cell,
  the mapping number, occurrence status, procedure, **every** quote with
  its locator, the rationale (if chosen), and any cross-domain pair.
- Cell metadata: `mapping: direct`, confidence, and for each mapping its
  number, occurrence, and numbered `source_quote n` and `source_locator n`
  pairs.
- Layer metadata: each source with its publication date, the ATT&CK
  version mapped, the verification status and date, the confidence
  threshold, the generation date, `generated by` (from the mappings file;
  the user can edit it before distributing the layer outside the team), one
  `check:` line per check result, and `status: DRAFT` when ATT&CK content was
  not checked.

## Building a layer by hand (no shell only)

Top level: `name`, `versions` {`attack`: major version string, `navigator`:
current release string, `layer`: "4.5"}, `domain` (as above),
`description`, `layout` {`layout`: "side", `showID`: true, `showName`: true,
`expandedSubtechniques`: "annotated"}, `techniques`, `gradient` {`colors`:
["#ff6666", "#ffe766", "#8ec843"], `minValue`: 0, `maxValue`: 100},
`legendItems` (High, Moderate, Low), `selectTechniquesAcrossTactics`: true,
`selectSubtechniquesWithParent`: false, `metadata` (name and value strings).

Each technique entry: `techniqueID` ("T####" or "T####.###"), `tactic`
(current lowercase hyphenated shortname for that domain), `score` (100, 66 or
33), `color` (the matching hex), `comment` (string), `enabled`: true,
`metadata` (objects with string `name` and `value`, or `{"divider": true}`),
`links` (`label` and an https `url`), `showSubtechniques` (true on a parent
whose sub-technique is mapped; a parent display entry gets no `score` and an
empty `color`). Every sub-technique needs its parent entry under the same
tactic. No duplicate technique and tactic pairs. Valid JSON, no comments, no
trailing commas.

After building by hand, report: local structure checked by eye; ATT&CK
content, quote verification, full schema and Navigator import all NOT
CHECKED. Label the layer a draft.

## ICS tactic shortnames (v19)

initial-access, execution, persistence, privilege-escalation, evasion,
discovery, lateral-movement, collection, command-and-control,
inhibit-response-function, impair-process-control, impact. Confirm with
`tactics --domain ics` whenever a shell is available.

## F. Feedly comparison layer (Step 8 only)

- Separate file. Name: "[Layer name]: Feedly comparison ([Domain]
  ATT&CK)". Same `versions`, `domain`, `layout` and parent display entry
  rules as the main layer.
- Colours must not reuse the confidence colours, so nobody mistakes this
  layer for the mapping:

| Group | Colour | Score |
|---|---|---|
| Corroborated | `#3d7ecb` (blue) | 100 |
| New for this entity | `#a05eb5` (purple) | 66 |
| Not in this report | `#c2c2c2` (grey) | 33 |

- Legend with the three groups. The `gradient` stays as in the main layer
  but is unused because every entry sets `color`.
- Comment per cell: group, entities, Feedly article count and window, up
  to three article titles. For mapped techniques, also the mapping
  number(s) and confidence. For "Not in this report": "Reported for
  [entity] elsewhere; not observed in this source."
- `links`: the technique page and up to three Feedly article URLs.
- Layer metadata: everything the main layer carries, plus `feedly query
  date`, `feedly window`, the entities, and `layer type: Feedly comparison
  (context only, not a mapping)`.
- Where several entities are compared, one entry per technique and tactic
  takes the strongest group in this order: Corroborated, New for this
  entity, Not in this report. The comment lists the result per entity.
- A parent-level match (Feedly has the parent and the mapping has a
  sub-technique, or the reverse) counts as Corroborated, and the comment
  says "parent-level match".
