# Reference E. Update mode

Read this at Step 0 when the user gives a tracker link or file, or asks to update a tracker or what changed. Budget about 15 turns.

1. **Find the tracker.** Use the link or file the user gave. Otherwise list the user's Dashboard artifacts and match the title `<attack> Attack Tracker`. If the user attached the earlier `tracker.json`, or it is still at the top of the working directory, prefer it, because it keeps the quotes. If you only have the dashboard, read its `datasets/tracker` document and fetch the asset it points to (`tracker-rows.json`), then rebuild `tracker.json` by grouping rows on their `collection` field, leaving out the rows the helper adds (`ir_metrics`, `tactics`). Those claims come back without quotes; keep them as they are.
2. **Save the old file and migrate.** Copy it to `work/tracker.prev.json` before you change anything, then run `python3 work/scripts/tracker_tool.py migrate tracker.json`, which brings the tracker up to the current schema (technique rows without a `ttp_id` get one, and attribution Evidence rows become Signal rows with `for_signals` and `against_signals`). If `migrate` renamed any attribution row, the dashboard template is out of date: write the current template once (Reference C, Update runs).
3. **Collect only what is new.** Brief the collection subagent (Reference G) to search for reporting published since `summary.newest_source_date`, not since `as_of`: a first run can carry a current date on old reporting, and searching from `as_of` would skip the missing months. Also have it retry every source whose `retrieval` is "failed" or "summarised", using the page-text tool when the user allows it, chase every named originator behind a blocking gap, and re-read any source whose date has changed.
4. **Merge with `add` or `set`.** Append new sources, claims, events, victims, techniques, and gap, watch and action rows with new IDs. Never delete or renumber a row. When a new source replaces a claim, mark the old one Superseded with `superseded_by`. When a new independent originator supports a Reported claim, upgrade it to Confirmed and update `corroboration`. Close a gap by setting `status` to Closed and `closed_by` to the claim that answers it; never remove the row. A retried source that now reads changes `retrieval` to "read" or "excerpts", and its gap closes with `status` Closed and `closed_by`.
5. **Increment** `summary.iteration`, set `as_of`, and rewrite the summary (bottom line) so its first sentence is the most significant change since the last run. Keep `summary.created` as it is.
6. **Log the changes.** Run `python3 work/scripts/tracker_tool.py diff work/tracker.prev.json tracker.json > work/rows/changes.json`. It compares every collection (new rows, removed rows and changed fields, including a reworded claim whose status did not change, and gaps closed), stamps each row with the new iteration, and continues the change IDs from the highest one already in the file. Edit each `item` so a reader understands it without the ledger, then `add` it. A Removed row means a row was deleted by mistake: restore it from `tracker.prev.json`, mark it Superseded or Closed, and run `diff` again.
7. **Validate and rebuild.** Run Step 12, then Step 13. For the dashboard, follow the update-run procedure in Reference C: upload the new `tracker-rows.json` and update `datasets/tracker` once. The change log shows the latest iteration by itself.
8. **Hand over** with what changed first.
